# Markdownの文書をHTML資料に作り直す

元の文書の見出しの順に、HTMLの部品を並べただけのものは完成ではない。読み手が最初の画面で目的と結論をつかめて、情報の種類ごとに合った図表で読めるところまで作る。

## 手順

1. Markdown全体を読み、次の3つを決める。決めた内容は、HTMLを書く前に作業メモへ書き出す。
   - 資料の目的: 読み手がこの資料を読んで、何を判断し、何をするか
   - 読み手: 誰が、どこまで読むか。読み手が複数いれば、それぞれの読む範囲
   - 情報の仕分け: 主要な結論、重要事項、詳細、補足
2. デザインシステムを確かめる。ユーザーが指定したもの、添付されたもの、プロジェクトにあるものの順に探し、あればそれに従う。なければ、HTMLを公開する先のデザインの指針に従う。
3. [情報設計の基準](references/information-design.md)に従って、構成案を作る。構成案は、節ごとに「載せる情報」「選ぶ表現」「元の文書の節」を並べた表にする。表現は[情報と表現の対応](references/representations.md)から選ぶ。
4. 構成案が[情報設計の基準](references/information-design.md)の「元の文書の順のまま」の項目に当たらないかを確かめる。当たるなら、手順3に戻る。
5. HTMLとCSSを書く。[HTMLを書くときの注意](references/html-pitfalls.md)に従う。
6. `scripts/render.sh <HTML> <出力先>` で、幅1280pxと幅375pxのスクリーンショットを撮り、はみ出しを調べる。スクリーンショットをすべて見て、崩れを直す。直したら、もう一度撮る。
7. 文章を推敲する。[文章の推敲](references/wording.md)に従う。
   1. `scripts/diff-from-source.py <HTML> <元のMarkdown>` で、画面の文のうち元の文書にない文を一覧にする。一覧の文を「書かない型」と照らし合わせ、当たる文を直す。
   2. `scripts/extract-text.py <HTML>` で画面の文字列を取り出し、`tenmaru` スキルで文を直し、`bunfmt` スキルで表記を1回検査する。
   3. 推敲で文を変えたら、1をもう一度実行する。
8. [完成条件](references/review-checklist.md)を1つずつ確かめる。満たさない項目があれば、該当する手順に戻る。
9. 公開する。公開先に決まりがあれば従う。
10. 次を報告する。
    - 情報ごとに選んだ表現
    - 元の文書にない言い方を補った箇所と、その根拠
    - 表示を確かめた幅と、確かめていない幅
    - bunfmtの指摘のうち、残したものとその理由

## 守ること

- 元の文書にない事実、仕様、数値、分岐を足さない。元の文書から導いた文を足したら、手順10で報告する。
- 条件、例外、注意、未確認の事項、コード、設定値を省かない。
- ユーザーから構成や表現の指摘を受けたら、指摘された箇所だけを直さず、手順1からやり直す。
