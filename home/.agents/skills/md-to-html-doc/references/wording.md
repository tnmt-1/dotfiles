# 文章の推敲

## 直す対象

- 本文、リード文、要点パネル、図の注記、表のセル、ボタンの文言
- 元の文書から写した文も、主張を変えない範囲で直す

## 直さない対象

- 画面の見本に出す文字列（ログイン画面のエラーメッセージなど）
- コード、API、識別子、引用、外部の基準の名称

## HTMLで起きやすいこと

- 要点パネルや注記で、体言止めが続く。元の文書に同じ内容の文があれば、それを使う。なければ文として書く
- 見出しを短くしようとして、記号でつなぐ。「＋」「→」を語句に戻す
- 「5と6を選ばなければ」のように、選択肢の番号だけで条件を書く。選ぶ案の名前を書く
- 番号と語句を半角の空白でつなぐ（「2 全テナント」）。番号は丸印の部品にするか、「（2）」の形で添える
- 「例」「注」のあとのコロンは、bunfmtの追加の決まりに従う

## 書かない型

- 元の文書の用語を、別の動詞や名詞に置き換えない
  - 例: 「ブロックする」「ログインできない」→「止める」「止まらない」「止め方」
  - 直し方: 元の文書の用語を使う。短くしたいときも、用語は変えない
- 見出しの直後に、節の中身を先に要約する文を置かない
  - 例: 「対象は…である。止めるのは…で、…ではない。止め方には…がある。」
  - 直し方: 削る。目的や前提として必要なら、元の文書の箇条書きをそのまま使う
- 「Aであり、Bではない」の対比を、自分で作らない
  - 例: 「止めるのはユーザーで、IPアドレスではない」
  - 直し方: 元の文書にある形だけを使う
- 見出しと要点パネルを、目を引く言い方にしない
  - 例: 「何を止めるか」「IPアドレスではなく、ユーザーを止める」「◯◯は必ず変更する」「伝えると、できること」
  - 直し方: 何が書いてあるかを示す名前にする。例: 「前提」「ユーザーをブロックする理由」
- 推敲で、短い断定文を足さない
  - 例: 「待ち時間は1分で済む」「約30回になる」
  - 直し方: 元の文書に理由の文があれば、それを使う

## bunfmtの検査で残してよい指摘

- 「文末が。で終わっていません」: ラベル、表のセル、箇条書きの項目では残す
- 文が長すぎる: 目次やナビゲーションの項目がつながって1文に見えているとき
- です・ます調の混在: 画面の見本の文字列のとき
- かぎかっこの対応: リンクの前後で文字列が分かれて取り出されたとき
- 「に」が1文に2回: 元の文書の問いで、2つの節を並べた形のとき
