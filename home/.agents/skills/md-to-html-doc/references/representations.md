# 情報と表現の対応

## 対応表

| 情報 | 表現 |
| --- | --- |
| 結論、要点 | リード文、要点パネル |
| 処理の流れ、現状の仕組み | フローチャート（SVG）。問題の経路を色と注記で示す |
| 人やシステムのやりとり | シーケンス図（SVG） |
| 決める順番、作業の順番 | ステップ表示（矢印でつないだ横並び） |
| 選択肢の比較 | 比較表。行を選択肢、列を観点にする |
| 2つの立場や利点と欠点 | 2列の比較パネル |
| 数値の比較 | 横棒。値のラベルを棒の横に置く |
| 段階的に変わる数値 | 棒グラフ。値のラベルを各棒に置く |
| 時系列 | タイムライン（横軸を時刻にした帯） |
| 条件による分岐 | 判断フロー（SVG、またはHTMLの分岐） |
| システムの構成、要素の関係 | 構成図、関係図（SVG） |
| 数値や設定値、APIと返す値 | 表 |
| 画面の表示の違い | 画面の簡単な見本を並べる |
| 選択肢と影響の対応 | 選べる表。選ぶと、最後の行と構成図が変わる |
| 注意、制約 | 注意喚起パネル |
| 未確認の事項 | 「未確認」のラベルを付けたパネル |
| 長い説明 | 要点を先に1文で書き、詳細を後ろに置く |

## 表現ごとの注意

- 図にしても新しい情報が増えないものは、文章のまま残す
- 元の文書のMermaidは、そのまま描き直さない。読み手が見るべき経路を色や太さで示す
- フローチャートで線が交差しそうなときは、戻りの線を引かず「◯◯へ戻る」という終端の箱にする
- 画面の見本には、画面名、項目のラベル、入力例、ボタンの文言、既存のリンクを入れ、実際の画面と同じ見た目にする。枠と色の帯だけでは、何の画面か分からない
- 案に「画面の部品を足す」ものがあれば、同じ役割の部品がすでに画面にあるかどうかを、ユーザーへ確認する
- 画面の見本で文言が決まっていない箇所は、［ブロック中であることと、何分後に試せるか］のように［］で内容だけを示し、文言が決まっていないことを添える
- 選べる表の初期値は、元の文書にある案の組み合わせにする。元の文書で決まっていない項目は、例として選んだことを書く
- 選べる表は、元の表と同じ行と列を保つ。元の表を別に残さなくてよい
- 判断フローに、元の文書にない枝を足さない
