# Git & コミットメッセージ規約

このスキルは、プロジェクトにおける Git の操作およびコミットメッセージの記述に関する基準を定義します。

## 0. 制約条件

- コミットは絶対にしないでください。コミットメッセージの作成のみです。
- ただし、ユーザーからコミットの指示があった場合のみ許可します。

### コンテキストの扱い

- コミットメッセージは**コミット対象の差分（staged / unstaged diff）を一次情報**として生成してください。
- これまでのセッションでのやり取りの内容は原則として参照せず、差分に含まれる変更内容のみからメッセージを構成してください。
- ただし、やり取りの中にコミットメッセージに役立つ背景・意図・変更理由などが明示されている場合に限り、それを補足情報として使用しても構いません（diff の内容を優先すること）。

## 1. コミットメッセージ規約 (Conventional Commits)

メッセージは以下の形式で記述し、言語は **日本語** を使用してください。
コピペしやすいように、コードブロックで出力してください。

### 形式

`type: description`

### 型 (Type)

- **feat**: 新機能の追加
- **fix**: バグ修正
- **docs**: ドキュメントのみの変更
- **style**: コードの意味に影響を与えない変更（ホワイトスペース、フォーマット、セミコロンの欠落など）
- **refactor**: バグ修正も新機能追加も行わないコード変更
- **test**: 不足しているテストの追加や既存のテストの修正
- **chore**: ビルドプロセスやドキュメント生成などの補助ツール、ライブラリの変更

### 記述ルール

- **現在形 (Imperative mood)** を使用する（例：「Add feature」であり「Added feature」ではない）。
- **簡潔さ**: 一行目は 50 文字以内を目指す。
- **詳細**: 必要に応じて 2 行目を空行とし、3 行目以降に箇条書きで詳細を記述する。

## 2. コミットの粒度

- [ ] **アトミックコミット**: 1 つのコミットには 1 つの論理的な変更のみを含める。
- [ ] **ビルド可能性**: どのコミットの状態でもコードがビルド可能（またはテストが通る）状態を維持する。
- [ ] **不要なファイルの除外**: 一時ファイルやキャッシュ、機密情報が含まれていないことを確認する。

## 3. 差分取得方法

以下の優先順で確認して下さい

1. プロンプトに指示があれば、その方法で差分を確認する
2. もし、指示がなければ、`git --no-pager diff --staged`で確認する
3. `2.`で差分が見つからない場合は、`git --no-pager diff`で確認する
