# 監視とレビューの観点

観点を増やすときはここに足す。SKILL.md の手順は触らない。

## 監視中に止める兆候（手順5）

見えたら `Ctrl+C` で止め、修正指示を送るか指示書を書き直す。

- 担当範囲外のファイルを開いている、または編集している
- 計画にないファイルを作ろうとしている
- 同じエラーを繰り返している
- 承認待ち（例 pi の `rm *`）で止まったまま進まない

## 差分レビュー（手順7）

```bash
jj diff
```

- 計画どおりか。勝手な追加や省略がないか
- 担当範囲外のファイルを触っていないか
- 完了条件のコマンドが実際に通るか
- 全体のユニットテストで、手順1の記録になかった失敗が増えていないか
- 指示書に書いた規約（コミット粒度、最後のリファクタ、セルフレビュー）に沿っているか
- 手順6の指摘（`/ponytail-review` の delete/stdlib/yagni、python スキルのレビューの指摘）が直っているか。見送った指摘に理由が付いているか
- 指示書で読ませたスキルの観点（例 `python` スキルの references）から逸脱していないか
